第1回

今回はpythonとはから始まり、基本文法・演算子までをまとめる。

1 pythonとは

　pythonとはRと同じインタプリタ言語である。インタプリタ言語の特徴としては記述が簡単という点が挙げられるだろう。その他にはコンパイル言語と呼ばれるCやJavaなどが存在する。コンパイル型言語はインタプリタ言語に比べ記述が一般的には難しい。その代わり、コンパイルした後のコードを動かすため処理が速い点がメリットとして挙げられる。 　

　現在のpythonはpython3であり、python2に修正が加えられ使いやすくなっている。またパッケージ管理はpipが主流？であったが、今はどうやらuvで管理するのが良いらしい。ただし注意点としてはuvはまだバージョンが1を超えていないため注意が必要である。（唐突に極端な変化が加えられて動かなく可能性があるため。）

　この勉強会ではuvを使っていきたいと考えているため、この資料もパッケージをとってくる際はuvの記法になっていることをあらかじめ了承いただきたい。

2 仮想環境とパッケージ管理

　ここでは勉強会で用いる仮想環境とパッケージ管理について簡単に記述する。勉強会では前でも述べたようにuvを使用する。uvは公式サイトに従ってターミナルから入手できる。

　uvのメリットはたくさんある。その中でも、パッケージ管理が楽であることと、処理が速いことが挙げられるだろう。pythonも仮想環境もパッケージ管理もuv1つで行うことができる。

　uvをダウンロードできたら任意のディレクトリを作成し、そこにuv環境を構築する。まずはuv initでプロジェクトを作成し、uv venv --python **でプロジェクトのpythonのバージョンを指定しながら仮想環境を構築できる。特定のバージョンのpythonを扱いたい時は、uv python install **でpythonをインストールできる。

　パッケージ管理はuv add **で行う。

3 実際に動かす

　pythonを実際に動かしてみる。例によって「Hello, World!」とでも返すようなものを書いてみよう。

print("Hello,World!")
Hello,World!

　実際に動いただろうか。もし動かなかった場合は自分が参照しているpythonの場所を確認して設定し直して欲しい。

4 変数と代入

　変数とはその名前の通りに変化する値のことである。ただし数値ではなくていい。pythonにおいて変数を扱うには以下のように記述する。

x = 10
print(x)
10

ここで、xは変数である。このxと10を繋いでいる=は代入演算子と呼ばれ、右辺を左辺に格納する役割を持つ。

　ちなみにRの記述をすると以下である。

x <- 10
print(x)

であり、代入演算子は<-である。

　=であるが、pythonの中ではこれは式を表していないことに注意されたい。なので後ほど詳しく書くが、以下の文は正しい記法である。

x = 2
x = x + 1
print(x)
3

　また、代入についてpythonは右辺そのものを左辺に格納していない。メモリ上にあるアドレスを格納している。この性質を理解するために以下の文を見てほしい。

num1 = 10
num2 = num1

print(id(num1))
print(id(num2))
4346635256
4346635256

　以下の文もこの性質によりかける。

x = [1, 2, 3]
y = x
y.append(4)

print(x)
print(y)
[1, 2, 3, 4]
[1, 2, 3, 4]

　これをRでかくとこうなる。

x <- c(1, 2, 3)
y <- x
y[4] <- 4

print(x)
print(y)

　これで代入についての概要は理解できたのではないだろうか。

　またデータ型の分類が複数存在する。例としては整数型や、文字列型などである。これら型の値のことをリテラルと呼ぶ。加えてそれぞれの型には性質がある。

これら性質はこれからも扱っていくのでイメージできるようにしておきたい。例えば、リストはコンテナーでミュータブル型であり、タプルは順序つきのリストでイミュータブル型である。

5.1 算術演算子

　算術演算子をまとめると以下の Table 2 である。

　これは数値以外でも用いることができるが組み合わせによっては演算できないものが存在する。

print(15 + "30")

以下のコードは上の文を改め数値型と文字型に直して演算したものである。

print(15 + int("30"))
print(str(15) + "30")

　算術演算については上の通りであるが、コンピュータ上（主にプログラミング）においては小数の演算には注意されたい。簡単に理由を説明しておくと、コンピュータ上で扱っている数値は我々の10進法とは違い2進法で基本的には動いている。例えば我々は0.1 = 1/10なので扱いやすいが、コンピュータでは扱いにくい数値である。それは位が\frac{1}{2}, \ \frac{1}{4}, \cdotsとなるためである。

5.2 代入演算子

　演算記号を\starと定義すると代入演算子は以下の性質を満たす。

i \star = j \Leftrightarrow i = i \star j \tag{1}

ここで\starは前節で紹介した算術演算子などを用いることができる。 例を見てみよう。

i = 10
i += 1
print(i)
11
i = 10
i = i + 1

ともに同じ結果が出力されたであろう。

5.3 ミュータブルとイミュータブル

これは代入を理解していれば理解しやすい。以下のコードを見てほしい。

dat1 = [1, 2, 3]
dat2 = dat1
dat1[0] = 100
print(dat1)
print(dat2)

x = 1
y = x
print(id(x))
print(id(y))
x += 10
print(x)
print(y)

print(id(x))
print(id(y))
[100, 2, 3]
[100, 2, 3]
4346634968
4346634968
11
1
4346635288
4346634968

　1つ目のコードは代入は同じオブジェクトのアドレスを指しているのでdat1の結果はdat2にも影響する。しかし、2つ目のコードはどうだろうか。xの結果がyには影響していない。

　これはリストがミュータブルな型であるのに対し、整数型はイミュータブルな型だからである。idを見るとわかるように、xに追加的な操作を加えた時に、すでに別オブジェクトとして格納されているのである。

5.4 比較演算子

　比較演算子は、左辺と右辺の値を比較し、その結果をTrue/Falseで返す。

< , >は異なる型同士での比較はエラーになる。=, !=は異なる型同士でも比較できるが一般的にはFalseを返す。

比較演算子を利用する上で、同一性と同値性を区別することは大切であるので、以下にまとめる。

  • 同一性：参照値が同じオブジェクトを参照していること
  • 同値性：オブジェクトが同じ値を持っていること
#同じ値を持つリストを生成
data1 = [1, 2, 3]
data2 = [1, 2, 3]

print(data1 == data2)
print(data1 is data2)
True
False

上記コードの結果を見れば一目瞭然だろう。同じ中身であるがリストとしては別オブジェクトになっているのである。つまり==は同値性を確認する演算子であり、isは同一性を確認する演算子である。

しかしイミュータブルな型での比較は注意されたい。下のコードを見てみよう。

#同じ文字列のデータを生成
data1 = 'abc'
data2 = 'abc'

print(data1 == data2)
print(data1 is data2)
True
True

　先ほどのコードの結果から予測すれば、data1とdata2は違うオブジェクトであるためisはFalseを返すはずであるが、実際はそうではない。これは文字列がイミュータブルであるための挙動だ。イミュータブルであれば後から値が変化することはないはずなので、Pythonではメモリを節約するために同じ値を再利用している。

Tip追記 
#同じ文字列のデータを生成
data1 = 'あいう'
data2 = 'あいう'

print(data1 == data2)
print(data1 is data2)
True
False

この場合だとイミュータブルであるはずなのに、isはFalseを返す。なぜなのかをGeminiに聞いてみた。

Geminiの回答：

data1 is data2 が False を返す理由は、Pythonのメモリ最適化機能である文字列インターン（String Interning）の仕様によるものです。

Pythonはメモリを節約するため、短い半角英数字（ASCII文字）などの特定の文字列を自動的に1つのメモリ領域に使い回します（そのため 'abc' is 'abc' は True になります）。しかし、'あいう' のような日本語（非ASCII文字）はこの自動再利用の対象外であるため、別々のメモリ領域に異なるオブジェクトとして生成されます。

さらに、1つのコードブロック内でまとめてコンパイルされる場合と、対話環境（REPLやノートブック）で1行ずつ実行される場合とでもコンパイラの最適化の働き方が異なるため、イミュータブルな型であっても is の結果は実行環境や文字種によって変化します。

そのため、値そのものが等しいかを比較したい場合は必ず == を使用し、is は None の判定（is None / is not None）専用として使い分けるのが原則です。
